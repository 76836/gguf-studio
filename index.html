Structural layer drop (real speedup)

Zeroing weights does not make inference faster. Dropping whole blk.N blocks does — tensors are removed, remaining blocks are renumbered, and *.block_count metadata is updated. Export a new GGUF after this.

Load a GGUF to list layers.

3. Selective quantize / prune (weight magnitude)

Built-in quantizers: F32, F16, Q8_0, Q4_0, studio-Q2_0. Selected tensors are dequantized → requantized and stored as overrides; Export rebuilds a full GGUF with corrected offsets and sizes. Magnitude prune zeros small values (does not remove layers).

4. In-browser fine-tune (tiny models)

Runs entirely in this tab. Masters stay F32 for gradients. Optional fake-quant forward (Q4_0 / Q8_0 / Q2_0): each step quantizes→dequantizes weights (STE) — this is QAT-style, not pure integer training. Aimed at models on the order of ~1–50M params, short sequences. Larger will be very slow or OOM.

5. Notes

  • Quant export: F32, F16, Q8_0, Q4_0, and studio Q2_0 (simple 2-bit; not ggml Q2_K / ternary Bonsai — those need native tools).
  • Train in Q4/Q2? Forward can fake-quant; backward always uses F32 masters. Pure integer Q4 training is not supported.
  • Q2_0 studio format is for experiments inside this app. For llama.cpp deployment prefer Q4_0/Q8_0/F16.
  • All work stays local in the tab.
